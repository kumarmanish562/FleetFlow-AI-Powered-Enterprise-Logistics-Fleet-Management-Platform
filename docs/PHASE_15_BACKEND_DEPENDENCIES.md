# Phase 15 backend dependencies

This list reflects the Spring controllers and DTOs present in this repository. The frontend does not substitute fixture data for missing operations.

| Module | Available contract | Remaining dependency |
| --- | --- | --- |
| User management | `GET /api/v1/auth/me` and public registration | Protected user directory, user status changes, and role administration APIs. Do not expose public registration as admin provisioning. |
| Billing | Invoice create and lookup by ID; payment create and lookup by ID under an invoice; financial analytics summaries | Invoice list/search and payment history list endpoints. Invoice lookup is authorized only for `ADMIN`, `BILLING`, and `CUSTOMER`; `BILLING` is not in the currently declared `RoleName` enum. |
| Tracking | Latest tracking event and event history by shipment ID | Fleet-wide active shipment/location feed, WebSocket/SSE contract, route geometry, and map-provider configuration. The UI uses REST polling for a selected shipment. |
| Maintenance | Per-vehicle history, create, update, start, complete, cancel; upcoming and overdue records | Fleet-wide all-status maintenance register endpoint. Existing upcoming/overdue APIs do not replace a complete register. |
| Shipment history | Shipment lookup/list and tracking events by shipment ID | Dedicated shipment status audit/history endpoint. |
| Customer account history | Customer profile and shipment data endpoints exist separately | Customer-scoped shipment/invoice/payment history endpoints, subject to API ownership and authorization rules. |
| Route dispatch | Route create/list/detail | Route assignment, dispatch, completion, and route geometry APIs. |
| Driver performance | Driver summary and analytics performance endpoints | Driver delivery-history endpoint if a per-driver auditable event history is required. |

## Contract notes

- Backend role enum values are `SUPER_ADMIN`, `ADMIN`, `FLEET_MANAGER`, `DISPATCHER`, `DRIVER`, `CUSTOMER`, and `FINANCE_MANAGER`.
- Some controller authorization annotations use `BILLING`, even though that role is absent from the enum. Frontend routes follow the actual role enum and only expose invoice lookup for `ADMIN` and `CUSTOMER`.
- Driver creation requires a pre-existing `userId`; current user provisioning is not available through a protected administrative endpoint.
- Tracking coordinates appear only when an event response contains them. No coordinates are generated by the frontend.
